# Bossing Pages Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** add `/bossing` (ladder, F2P view, collection log) and `/bossing/<id>` boss pages (Loot & collection log, Guide, Achievements) to RS3 Compass.

**Architecture:**
- **Imported data:** a by-hand importer turns the Wiki's Bosses table and boss pages into `src/bossesImported.ts`.
- **Hand-written data:** `src/bossGuides.ts` adds guide text.
- **Logic:** pure modules in `src/lib/` (ladder, loot, collection log), each covered by `node --test`.
- **Prices:** live GE prices come through a cached `/api/prices` route.
- **Pages:** Svelte pages reuse the quest page's shell components.

**Tech Stack:** SvelteKit 3 with Svelte 5 runes, TypeScript, adapter-node (Deno Deploy), `node --experimental-strip-types --test`.

**Spec:** `docs/superpowers/specs/2026-11-13-bossing-design.md` (approved 2026-11-13). Read it before any task; the mockups are on the canvas it links (boards BO1–BO4).

## Global Constraints

- **No new dependencies.**
- **Line endings:** CRLF. Edit files only with the Edit/Write tools, never with scripts.
- **Commits:**
  - Plain imperative subject, no `feat:` style prefixes, no attribution lines.
  - Author: `git -c user.name="Alex Mollard" -c user.email="47443168+AlexMollard@users.noreply.github.com" commit`.
  - Don't push.
- **Checks after every task:** `npm test`. After any `.svelte` or route change, also `npx svelte-kit sync && npx svelte-check --tsconfig ./tsconfig.json --threshold warning`.
- **Network:** the Wiki API is called only from `scripts/`. weirdgloop is called only from `src/lib/server/priceLookup.ts`. User agent: `RS3 Compass boss import (https://github.com/AlexMollard/RS3-Compass)` for the importer; the existing app user agent for prices.
- **Tier labels:** `Free`, `Low`, `Mid`, `High`, in that order.
- **Recommended stats per tier:** `{ Free: 60, Low: 75, Mid: 85, High: 95 }`.
- **Stage headings:**
  - Free → "Start here"
  - Low → "Early members"
  - Mid → "Mid-game"
  - High → "Endgame"
- **Collection log key:** `boss:<bossId>:<item name>`. Item names are kept verbatim.
- **Packing key for boss pages:** `packKey("boss-" + bossId, line)`.
- **Price cache:** expires after 1 hour. Prices are fetched from `https://api.weirdgloop.org/exchange/history/rs/latest?name=A|B|…`.
- **Copy:** "Guide coming", "Wiki strategy ↗", "Prices unavailable", "auto from activity", "Levels not recorded", "N drops unpriced".

## Review Focus

1. **A profile with no recorded levels** (a hand-made profile with an empty `levels` map) → every non-quest-gated boss reads "Levels not recorded", and nothing throws. Test in Task 3.
2. **Prices endpoint down or partial** → the drop table renders. Missing items show "—", the average lists "N drops unpriced", and a total failure shows "Prices unavailable". Tests in Tasks 4 and 6.
3. **A boss whose page has no drop table at all** (some bosses keep drops on subpages) → `drops` is `{}`, the Loot tab shows the collection log from the signature drops and a "Drop table on the Wiki ↗" link instead of a table. Tests in Tasks 1 and 4.
4. **An old save without `collected` or `collectedAuto`** loads unchanged, and the log reads empty. Test in Task 5.
5. **A wrong auto-tick that the player unticks** stays unticked after the next sync. Test in Task 5.

**Interfaces — produces:**
- `parseBossesTable(wikitext): BossRow[]`. Reads only the `==Combat bosses==` section.

### Task 3: Ladder order and readiness

**Files:**
- Create: `src/lib/bossLadder.ts`
- Test: `tests/boss-ladder.test.mjs`

**Interfaces — produces:**
- `TIER_ORDER: Record<BossTier, number>` and `TIER_STATS` (the values under Global Constraints).
- `ladder(bosses: readonly BossRecord[]): BossRecord[]`: tier order, then level, then name.
- `visibleBosses(profile: Profile, bosses): BossRecord[]`: the ladder filtered to `!members` when `profile.mode === "f2p"`.
- `type BossStatus = { kind: "members" | "quest" | "skill" | "ready" | "levels" | "unknown"; text: string; quest?: string }`.
- `bossStatus(profile: Profile, boss: BossRecord): BossStatus`, applying the spec's rules in order:
  - members → "Members only"
  - first incomplete quest → "After <quest name>" with `quest` set to its id
  - an unmet skill requirement → "Needs <level> <Skill>"
  - meets the tier → "Ready now"
  - an empty `levels` map → "Levels not recorded", kind `"unknown"`
  - otherwise → "Around <N> combat stats", kind `"levels"`
- `meetsTier(levels: Record<string, number>, tier: BossTier): boolean`. Best style = max(min(Attack, Strength), Ranged, Magic). It needs best style, Constitution and Defence all ≥ `TIER_STATS[tier]`.
- `nextBoss(profile, bosses, collected: ReadonlySet<string>): BossRecord | undefined`. Returns the first visible boss that is "Ready now" and whose uniques aren't all collected; if there's none, the first visible boss that isn't ready.
- `stageOf(tier): string`: the stage headings above.
- `defaultDropVersion(boss: BossRecord, mode: Profile["mode"]): string | undefined`. The spec's rule:
  - f2p → first key containing "F2P", else the first key;
  - members → first key without "F2P", else the first key;
  - `undefined` when there are no drops.

### Task 4: Loot value maths

**Files:**
- Create: `src/lib/bossLoot.ts`
- Test: `tests/boss-loot.test.mjs`

**Interfaces — produces:**
- `rarityProbability(rarity: string): number | undefined`: `"Always"` → 1, `"a/b"` → a/b (commas allowed), anything else → `undefined`.
- `meanQuantity(quantity: string): number | undefined`. Strips `(noted)` and commas; `"a-b"` gives the midpoint.
- `type Prices = Readonly<Record<string, number>>`.
- `type LootRow = BossDrop & { price?: number; perKill?: number }`.
- `lootRows(drops: readonly BossDrop[], prices: Prices | undefined): LootRow[]`:
  - `Coins` is priced at 1;
  - `perKill` = price × meanQuantity × probability, set only when all three are known;
  - sorted by perKill descending, unpriced rows last in their original order.
- `lootSummary(rows: LootRow[]): { average: number; unpriced: number; top: LootRow[] }`. `top` is the 3 biggest contributors; unpriced counts rows without `perKill`.

- [ ] **Step 1:** tests:
  - `rarityProbability("3/520")` is about 0.005769.
  - `"1/5,000"` → 0.0002.
  - `"Common"` → `undefined`.
  - `meanQuantity("12000-16000")` → 14000.
  - `"14 (noted)"` → 14.
  - `lootRows` with prices `{ "Mole claw": 440 }` over `[{item:"Mole claw",quantity:"1",rarity:"Always"}, {item:"Coins",quantity:"100-200",rarity:"1/2"}, {item:"Mystery",quantity:"1",rarity:"1/10"}]` gives perKill 440, then Coins 75, then Mystery with no perKill.
  - `lootSummary` gives `{average: 515, unpriced: 1}` with `top[0].item === "Mole claw"`.
  - Review Focus 2: `lootRows(drops, undefined)` gives every row except Coins without `price`; the summary unpriced count equals drops.length − 1.
  - Review Focus 3: `lootRows([], {})` → `[]` and the summary is `{average: 0, unpriced: 0, top: []}`.

### Task 6: Live prices route

- Create: `src/routes/api/prices/+server.ts`
- Create: `src/lib/priceClient.ts`

**Interfaces — produces:**
- Server: `createPriceLookup({ fetch, now, ttlMs = 3_600_000 })` returns `{ prices(names: string[], client?: string): Promise<Record<string, number>> }`:
  - names are deduplicated and capped at 100 per request;
  - cached names are served from `LruMap<string, {price: number | null; fetchedAt: number}>(2000)`;
  - names that are missing or stale are fetched in one upstream call, with `upstreamInit("application/json", <app UA>)`;
  - a name absent from the reply is cached as `null`;
  - throttled per client with `createClientLimiter()`. When over the limit it throws an error carrying `retryAfter`.
- Route: `GET /api/prices?names=A|B` → `200 {prices}`. On upstream failure → `502 {error:"Prices unavailable"}`; when limited → `429` with `Retry-After`. Client address handling follows `api/player/+server.ts`.
- Client: `fetchPrices(names: string[]): Promise<Prices | undefined>`. Returns `undefined` on any failure.
